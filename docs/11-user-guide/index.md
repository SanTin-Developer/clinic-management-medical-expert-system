# 11 · User Guide

This guide walks through the screens a real user touches. It is organized by
role. If a screen is not listed for your role, your account does not have the
permission for it, and the backend will reject the action even if you type the
URL.

**Notation:** menu paths use the admin dashboard's sidebar. Every step below is
performed at `http://localhost:5173` locally, or the deployed admin URL.

> **Important:** this system records clinical and financial data. Do not share
> accounts. Do not write test data into a production database.

## 11.1 Before You Begin

| Item | Detail |
| --- | --- |
| Admin dashboard | `http://localhost:5173` |
| Public website | `http://localhost:5174` |
| API | `http://localhost:8000/api/v1` |
| Browser | A current evergreen browser |
| Account state | Must be `active`. Invited accounts stay `pending_approval` until an administrator approves them |

The roles are **Admin**, **Receptionist**, **Nurse**, **Head Nurse**, **Doctor**,
**Pharmacist**, and **Patient**.

## 11.2 Signing In

### Step 1: Open the login screen

Go to the admin URL. You land on `/login`.

### Step 2: Enter your credentials

Use your email address (or your username) and password, then submit.

### Step 3: Complete a second factor if your clinic enabled it

| Screen | When it appears | What to do |
| --- | --- | --- |
| `/login/verify` | Email OTP is enabled and this device is not trusted | Enter the 6-digit code from your email; resend after the cooldown |
| `/login/2fa` | TOTP two-factor is required | Enter the code from your authenticator app, or a recovery code |

All three gates are **off by default** in a new installation. Your
administrator decides whether to enable them.

### Step 4: First-time password setup (invited staff)

If you were invited, open the invitation link in your email. It lands on
`/accept-invitation`, where you set a password. Your account then waits for
approval before it can sign in.

### Step 5: Forgot your password

1. Open `/forgot-password` and submit your email.
2. Check your email for a 6-digit code.
3. Enter it at `/reset-password`.
4. Set the new password at `/reset-password/new`.

Password reset codes expire quickly and are rate-limited.

## 11.3 Receptionist Guide

Reception owns registration, scheduling, the queue, and outpatient billing.

### Step 1: Register a patient

1. Open **Patients** (`/patients`).
2. Choose **New patient**.
3. Fill in the demographic and contact fields and save.
4. The patient detail page (`/patients/:id`) shows documents and clinical tabs.

### Step 2: Upload a patient document

1. Open the patient record.
2. Use the **Documents** tab.
3. Choose a file and upload. Files are stored privately; size and type are
   validated.

Downloads use an authorized endpoint, so a copied link will not work for
someone without permission.

### Step 3: Book an appointment

1. Open **Appointments** (`/appointments`).
2. Create an appointment, choosing the patient, clinician, date, and time.
3. Save. Open it later at `/appointments/:id` to review or cancel.

### Step 4: Run the outpatient queue

1. Open **Queue** (`/queue`).
2. Add the patient to the queue, optionally linked to today's appointment.
3. Progress the entry through **Call → Start → Complete**.
4. Use **Skip** when the patient does not respond and **Cancel** when the visit
   will not happen.

Each transition is a separate action; there is no free-form status editor.

### Step 5: Raise an invoice

1. Open **Billing** (`/billing`).
2. Create an invoice for the patient and add service or medicine lines.
3. Save. Totals are calculated by the server.

### Step 6: Record a payment

1. Open the invoice at `/billing/:id`.
2. Choose **Record payment**.
3. Select the method — `cash`, `card`, `bank_transfer`, `insurance`, or
   `other` — and enter the amount.
4. Save. The balance updates from recorded payments.

No card terminal or gateway is contacted; the payment is a record of money
received elsewhere.

### Step 7: Print or download the invoice

On the invoice detail screen, choose **PDF**. The file is generated by the
backend on demand.

### Step 8: Admit a patient (inpatient)

1. Open **Admissions** (`/admissions`).
2. Create an admission and select a free bed.
3. The bed's status changes; the patient now appears in nursing views.
4. Inpatient charges and payments are handled on
   `/admissions/:id/billing`.

## 11.4 Doctor Guide

Doctors own the clinical record, prescriptions, and expert-system evaluation.

### Step 1: Open the patient

Use **Patients** and select the patient, or arrive from an appointment or the
queue.

### Step 2: Record a consultation

1. Open the consultation area for the patient.
2. Create a consultation with the presenting complaint and notes.
3. Add one or more diagnoses.

### Step 3: Review vitals and history

Nurses record vitals. Review them from the patient's clinical tabs before
deciding on treatment.

### Step 4: Consult the expert system (optional)

1. Open **Expert System** (`/expert-system`).
2. Select the symptoms that apply.
3. Submit the evaluation.
4. Read the matched rules, their priority, and the supporting symptoms.

The result is **rule matching, not a diagnosis**. `confidence_score` is a
configured weight, not a probability. Nothing here is a medical device.

If the service is unavailable you get an error and the consultation can
continue without it.

### Step 5: Write a prescription

1. Open **Prescriptions** (`/prescriptions`).
2. Create a prescription for the patient.
3. Add medicine lines with dose, quantity, and instructions.
4. Save. The pharmacist dispenses it later.

### Step 6: Review the medical record

Open **Medical Records** (`/medical-records`) for the consolidated view. Your
edits are auditable.

## 11.5 Nurse and Head Nurse Guide

Nurses handle vitals, records, ward work, and medication administration. Head
Nurses add ward/bed management, assignments, attendance, announcements, and
leave approval.

### Step 1: Record vitals

1. Open the patient's clinical tabs.
2. Add a vital-signs entry (temperature, blood pressure, pulse, and the other
   supported measurements).
3. Save.

### Step 2: See your assigned patients

1. Open the nursing workspace for your shift.
2. Only patients assigned to you are listed; assignment is enforced by the
   backend, not just the UI.

### Step 3: Work the nursing task board

1. Open **Nursing Tasks** (`/nursing-tasks`).
2. Pick a task, perform it, and mark it complete.
3. Overdue tasks generate notifications automatically on a schedule.

### Step 4: Record medication administration

1. Open **MAR** (`/mar`).
2. Find the scheduled administration.
3. Record **Administer** or set the appropriate status.
4. The entry records who administered what and when.

### Step 5: Manage wards and beds (Head Nurse)

1. Open **Wards** (`/wards`).
2. Create or edit wards, rooms, and beds.
3. Change a bed's status when housekeeping or maintenance requires it.

### Step 6: Assign nurses to patients (Head Nurse)

1. Open **Assignments** (`/assignments`).
2. Create an assignment between a nurse and an admitted patient.
3. End the assignment when the nurse's shift finishes.

### Step 7: Clock in and out

1. Open **Attendance** (`/attendance`) and use **Clock in** / **Clock out**, or
2. Scan the rotating QR code at `/attendance/scan` if your clinic uses the
   kiosk.

### Step 8: Run the QR attendance kiosk (Head Nurse)

1. Create an attendance session from the attendance screen.
2. Open `/attendance/kiosk/:sessionId` on the kiosk device. It runs full screen
   outside the normal layout.
3. The QR token rotates automatically; the session closes manually or when the
   scheduler finalizes it.

### Step 9: Approve leave

1. Open **Leave** (`/leave`).
2. Review a pending request.
3. Approve or reject it. Staff can cancel their own pending requests.

### Step 10: Publish an announcement

1. Open **Announcements** (`/announcements`).
2. Draft the announcement.
3. Publish immediately, schedule it, or save as a draft.
4. Archived announcements can be restored; readership is visible per
   announcement.

## 11.6 Pharmacist Guide

Pharmacists own the catalog, stock, dispensing, and POS.

### Step 1: Maintain the medicine catalog

1. Open **Pharmacy** (`/pharmacy`).
2. Add or edit a medicine: name, pricing, reorder level,
   `requires_prescription`, and active/recall state.
3. A recalled or inactive medicine cannot be sold or dispensed.

### Step 2: Receive or adjust stock

1. Open the **Inventory** tab (`/inventory`).
2. Create an inventory batch with quantity, expiry date, and location.
3. Record stock movements for receipts and adjustments.

There is **no supplier or purchase-order workflow** in this build. Batches are
created manually or through stock movements.

### Step 3: Dispense a prescription

1. Open **Prescriptions** (`/prescriptions`).
2. Open the prescription and review the lines.
3. Choose **Dispense**.
4. The system allocates batches, records stock movements, and reduces stock.
5. If stock is insufficient, dispensing fails and nothing is changed.

### Step 4: Sell at the POS

1. Open **Pharmacy → POS** (`/pharmacy/pos`).
2. Search for medicines and add them to the cart with quantities.
3. Optionally attach a patient and apply a discount.
4. Optionally take a payment and enter the amount received and the method.
5. Choose **Checkout**.

What the POS enforces:

- Prices and totals come from the server. The cart cannot send its own prices.
- A discount cannot exceed the subtotal.
- A payment, if supplied, must equal the total.
- Prescription-only, recalled, inactive, and out-of-stock medicines are
  rejected.
- Repeating the same checkout does not create a second sale.

The POS does **not** currently offer void or refund, and it does not accept a
prescription link.

### Step 5: Review the pharmacy dashboard

Open **Pharmacy → Dashboard** (`/pharmacy/dashboard`) for stock health, expiry
risk, and dispensing activity.

## 11.7 Administrator Guide

Administrators configure the system, manage people, and own the website.

### Step 1: Invite a staff member

1. Open **Invitations** (`/invitations`).
2. Enter the email address and role.
3. Send the invitation. Only a hash of the token is stored; the link is emailed
   once.
4. Resend or revoke from the same screen.

### Step 2: Approve a new account

1. Open **Approvals** (`/approvals`).
2. Review the pending account.
3. Approve or reject it. Approval requires a **step-up** confirmation.

### Step 3: Manage users and roles

1. Open **Users** (`/users`).
2. Change roles or update details.
3. Suspend, disable, or reactivate an account.

Suspension and disabling require step-up. The **last active administrator
cannot be suspended or disabled**.

### Step 4: Maintain the staff directory

1. Open **Staff** (`/staff`).
2. Create staff records with department, job title, contact details, and salary.
3. Link a staff record to a user account, or unlink it.
4. Upload staff documents; downloads are authorized.

### Step 5: Build the roster

1. Open **Scheduling** (`/scheduling`).
2. Create or reuse shift templates.
3. Assign shifts, check the board and uncovered shifts, then publish.

### Step 6: Review audit and security events

1. Open **Audit Logs** (`/audit-logs`) for activity history.
2. Review your own security events from **Settings → Security**.

### Step 7: Watch system health

System alerts appear in the notification area and on the dashboard. They are
generated on a schedule for inventory, inpatient billing, appointments, staff,
attendance, clinical, and infrastructure conditions. Acknowledge or resolve
them as they are handled.

Only administrators can see them, because they expose infrastructure state.

### Step 8: Manage the website

1. Open **Website** (`/website`) for the CMS dashboard.
2. Edit **Settings**, **Content blocks**, **Pages**, **Services**, **Team**,
   **Gallery**, and **Articles**.
3. Upload media in the **Media** library.
4. Publish or unpublish pages and articles.
5. Read the **Contact messages** inbox and mark messages read or unread.

Published content appears on the public website immediately — no code
deployment is required. Unpublished content is never returned by the public API.

### Step 9: Manage the knowledge base

1. Open the knowledge-base screens for diseases, symptoms, and expert rules.
2. Add or edit entries and rules.

The starter knowledge base is **not clinically validated**. Review every rule
with a qualified clinician before relying on it.

### Step 10: Export reports

1. Open **Reports** (`/reports`).
2. Choose a report: summary, appointments, revenue, or inventory.
3. Export as CSV or PDF.

Reports are an Admin-only permission in the default seeder.

## 11.8 Patient Role (Limited)

A `Patient` role exists and can sign in to the same dashboard with a restricted
permission set:

- View their own patient record.
- View their own medical records.
- View their own prescriptions.
- Create and cancel their own appointments.
- Read announcements.

**There is no separate patient portal.** Whether real patients use this role
operationally is **Unverified**. Most clinics in this build would keep patient
accounts disabled and treat patients as records only.

## 11.9 Public Visitor Guide

The public website needs no account.

| Task | Where |
| --- | --- |
| Learn about the clinic | `/` and `/about` |
| Browse services | `/services` |
| Meet the team | `/team` |
| See facilities | `/gallery` |
| Read health news | `/health-news` (also `/news`) |
| Send a message | `/contact` |
| Read legal pages | `/privacy-policy`, `/terms-of-use`, or any published CMS page under `/pages/:slug` |

The contact form is rate-limited. The site shows only published content and
never exposes patient or staff data.

Some homepage figures and partner names are design placeholders, not verified
clinic data — see
[08 · Frontend Documentation §8.2.5](../08-frontend-documentation/index.md).

## 11.10 Account Settings for Every User

Open **Settings** (`/settings`):

| Tab | What you can do |
| --- | --- |
| Profile | Update your details and avatar |
| Security | Change password, enroll or disable TOTP, regenerate recovery codes, review security events |
| Devices | Review and revoke trusted devices |
| Sessions | Review and revoke other active sessions |
| Preferences | Notification and UI preferences |
| Data | Export your own data or request account deletion |

Account deletion is a request; follow your clinic's retention policy before
acting on it.

## 11.11 Common Problems

| Symptom | Likely cause | What to do |
| --- | --- | --- |
| "This action is unauthorized" (`403`) | Your role lacks the permission | Ask an administrator; do not retry |
| Signed out unexpectedly | Token expired or revoked | Sign in again |
| "Too Many Attempts" (`429`) | Rate limit or lockout | Wait, then retry; ask an admin if you are locked out |
| Expert system error | Python service down or timed out | Continue the consultation; tell an administrator |
| POS rejects an item | Prescription-only, recalled, inactive, or out of stock | Correct the stock or the selection |
| Checkout returns an existing sale | The same checkout was submitted twice | Open the existing sale; do not re-enter |
| Upload fails | File too large or wrong type | Check the allowed size/type, or ask about the proxy body limit |
| Public page is missing | It is unpublished | Publish it in the CMS |
| Invited account cannot sign in | Still `pending_approval` | An administrator must approve it |
