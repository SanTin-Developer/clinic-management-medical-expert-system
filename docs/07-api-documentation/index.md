# 07 · API Documentation

The authoritative route list is `backend/routes/api.php`. Interactive
documentation is generated by Scramble:

- UI: `http://localhost:8000/docs/api`
- OpenAPI JSON: `http://localhost:8000/docs/api.json`

In `local`, docs are open. In other environments, the `viewApiDocs` gate restricts
them to authenticated administrators.

## 7.1 Global Standards and Conventions

### Base URL and protocol

| Environment | Base URL |
| --- | --- |
| Local | `http://localhost:8000/api/v1` |
| Docker network (server-to-server) | `http://backend:8000/api/v1` |
| Production | `https://<api-host>/api/v1` |

### Headers

| Header | When |
| --- | --- |
| `Accept: application/json` | All JSON requests |
| `Authorization: Bearer <token>` | Protected routes |
| `Content-Type: application/json` | JSON bodies |
| `Content-Type: multipart/form-data` | Uploads |
| `X-Step-Up-Token` | Suspend, disable, approve |
| `X-Internal-Api-Key` | Laravel → expert system |
| `X-Telegram-Bot-Api-Secret-Token` | Telegram webhook |

### HTTP status codes

| Code | Meaning |
| --- | --- |
| `200` | Success; also used for a duplicate POS idempotency key |
| `201` | Resource created |
| `204` | No content |
| `401` | Missing or invalid token |
| `403` | Authenticated but not permitted, or email/2FA gate |
| `404` | Resource not found |
| `422` | Validation or domain-rule failure |
| `429` | Rate limited or account locked |
| `500` | Unexpected server error |
| `503` | Dependency unavailable, such as a missing POS migration or expert service |
| `504` | Expert-system request timeout |

### Response conventions

- Success payloads use a `data` key, for example
  `{ "data": { "id": 1, "name": "..." } }`.
- List endpoints use Laravel pagination where pagination is enabled
  (`data`, `meta`, `links`).
- Validation errors use `{ "message": "...", "errors": { "field": ["..."] } }`.
- POS duplicate responses add `"duplicate": true` alongside `data`.
- File endpoints return binary streams (`application/pdf`, `text/csv`, or the
  stored file type).

### Rate limits

See [04 · System Design §4.5](../04-system-design/index.md) for the limiter
table: `api` 60/min, `login` 5/min, `otp` 5/min, `password-reset` 5/min, plus
dedicated limiters for 2FA, invitations, attendance scanning, and Telegram.

### Evaluate request

```json
{ "symptom_ids": [9, 13, 31] }
```

Limits: 1–50 unique, active symptom IDs. Empty and duplicate IDs are normalized.

### Evaluate response (shape)

```json
{
  "data": {
    "matched_rule_count": 1,
    "matched_rules": [
      {
        "rule_code": "RULE-FLU-001",
        "disease": "Influenza",
        "priority": 10,
        "confidence_score": 0.8,
        "matched_symptoms": [9, 13, 31]
      }
    ]
  }
}
```

Exact field names are defined in `expert-system/app/schemas.py` and surfaced by
Scramble. `confidence_score` is configuration, not a probability.

## 7.17 cURL Quick Checks

```bash
# Liveness
curl -i http://localhost:8000/up

# Public website
curl -i http://localhost:8000/api/v1/website/bootstrap

# Login (replace values; do not commit real credentials)
curl -i -X POST http://localhost:8000/api/v1/auth/login \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"email":"<local-user>","password":"<local-password>"}'
```

The Postman collection in `expert-system/postman/` covers the expert-system
flow. See its [guide](../../expert-system/postman/README.md).
